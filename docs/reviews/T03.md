**問題**

1. [blocker] `NeonRenderer` 效能：64 根線各自 `setShadow` 模糊，Release 14.6 ms／幀。**設計變更（設計負責人決定，任務單 §2 已同步修改）**：不再逐線加陰影，改成「每幀一次的低解析度光暈 pass」：
   1. trail（殘影，16-bit half-float）照舊每幀先 `destinationOut` 淡出。
   2. **glow buffer**：另一張 8-bit premultiplied sRGB bitmap，尺寸 = `ceil(wPx / d) × ceil(hPx / d)`，`d = isThumbnail ? 1 : 4`（size／scale／d 改變時重建）。每幀清空後，以相同幾何（座標縮放 1/d）用 `.plusLighter` 畫出所有線段（**不加陰影**，顏色與 alpha 同本體）。
   3. 用 vImage（`vImageTentConvolve_ARGB8888`，四個通道同時卷積，預先配置目的 buffer 與 temp buffer）模糊 glow buffer。對應原型 `shadowBlur`：`blur = isThumbnail ? 3 : 14 + 10·bass`（裝置像素），σ_full = blur / 2，σ_q = σ_full / d；tent 寬 `W = 2b − 1`、`b = max(2, round(sqrt(6·σ_q² + 1)))`。
   4. 把模糊後的 glow 以 `.plusLighter`、`interpolationQuality = .medium` 放大畫進 trail（鋪滿 size），再把線段本體（不加陰影）以 `.plusLighter` 畫進 trail；水平線照舊。
   5. trail 合成回目標（局部翻轉，維持現狀）。
   - 驗收：Release、520×200 pt @2x、全 1 frame **≤ 2 ms**（審查者量測）；目視光暈仍明顯且隨 bass 變大。
2. [major] `NeonRenderer.swift:90` — trail 是 half-float 但色彩空間用 extendedSRGB。float context 的 `plusLighter` 只夾 alpha 不夾顏色，預乘顏色會累積到數倍於 alpha，配合 extendedSRGB 在廣色域（內建 Retina，P3）螢幕上轉換時三通道全部爆白，aurora 低頻的青色變成白色（審查者實測 P3 目標 (212,255,255) vs 原型行為 (137,252,253)）。期望：half-float 保留，**色彩空間改 `CGColorSpace.sRGB`**（實測可得 (138,252,253)，殘影測試數值不變）。任務單 §2 已同步修改。
3. [major] `LedRenderer` 全 1 frame 2.15 ms（> 2 ms）。期望：批次化——未亮格全部收進一條 path 一次 fill；每一列的亮格收進一條 path 用該列顏色一次 fill；峰值格同理。目標 Release 全 1 ≤ 1.2 ms。
4. [major] `FrameClock.swift:28` — 只在 `start()` 時綁定一個 NSScreen，之後不再更新。拔掉外接螢幕、闔上筆電（clamshell）、調整排列時，唯一的 tick 來源停止 → 浮動視窗與選單列一起凍結（使用者有 3 個螢幕，實際會發生）。`start()` 時沒有螢幕也會靜默放棄。期望：觀察 `NSApplication.didChangeScreenParametersNotification`（main queue、weak self），記住建立 link 的 `CGDirectDisplayID`（`deviceDescription[NSDeviceDescriptionKey("NSScreenNumber")]`）；通知來時若 link 為 nil 或該 display 已不在 `NSScreen.screens`，就 `stop()` 再 `start()`（第一幀 dt = 0）。仍用 NSScreen 的 display link。
5. [minor] `StatusItemController.swift:74` — 節流每次重畫後把累積時間歸 0，兩次 60 Hz 回呼的 dt 加總常略小於 1/30 s（timestamp 抖動），實際只有約 20～22 fps。期望：`guard accumulatedTime >= 1.0/30 - 0.002`（60 Hz 下穩定每 2 次回呼重畫一次）。
6. [minor] 熱路徑效能一致性：AGENTS.md 已新增規則——每幀繪圖的內層迴圈不用 `for … in` 範圍（Debug 建置下每次迭代都 malloc）。期望：四個主題、MenuBarRenderer、PreviewSpectrumSource、Palette 的每幀迴圈改為 `while`（init／一次性建立的迴圈不用改）。
7. [nit→請一併處理] `FloatingPanelController.swift:11` — `onStateChange` 沒有任何人設定，是死碼；移除屬性與呼叫（選單已用 `menuNeedsUpdate` 同步狀態）。
8. [minor] 測試補強（每一條都已由審查者用 mutation 確認目前測試抓不到）：
   - **neon scale**：(a) 用 scale 1 的 bitmap（identity 縮放）但 `options.scale = 2` 繪製，斷言 offscreen 像素尺寸為 640×240（layer-backed `draw(_:)` 的 CTM 是 identity，用來抓「從 ctm 推 scale」的錯誤）；(b) 同一全 1 frame 在 scale 1 與 scale 2（bitmap 與 options 一致）的總 alpha 比值 ≈ 4（±0.8）。
   - **neon 無效 frame 重置殘影**：同一 renderer 畫全 1 → `silent(bandCount: 0)` → `silent(bandCount: 64)`，最後一張的總 alpha 等於新 renderer 畫 `silent(64)` 的結果；**fade = 1** 時殘影立即清除（與新 renderer 單幀 silent 相差 ≤ 1%）。
   - **neon 光暈存在且隨 bass 變大**：values = peaks = 1，bass 0 與 bass 1 各用新 renderer；頂部附近（例如 x 160、y 2，320×120 pt）bass 0 時 alpha > 0，bass 1 時明顯更大（> +5）。新光暈實作完成後重新確認門檻。

   - **配色快取**：同一個 BarsRenderer 先畫 aurora、再改 `look.palette = .ember` 畫，第一根柱子的紅色通道 > 200。
   - **bars 峰值帽／倒影／鏡像**：全 1 frame，(18,11) alpha > 200、(18,13) == 0、(18,89) == 0、(18,100) ≈ 41 ± 3；`mirror = true` 時 (18,100) > 100。
